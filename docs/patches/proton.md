# Patches on top of Proton (`macos` branch)

Base: `ValveSoftware/Proton` at tag `proton-11.0-2` (`db9e6ff`). Commits in `albvalort/Proton@macos`.

## lsteamclient (milestone 5)

| Commit | File | Problem | Fix |
|---|---|---|---|
| `40a8b6c` | `unixlib.cpp` | The macOS `steamclient.dylib` does not export `Steam_IsKnownInterface` or `Steam_NotifyMissingInterface`, and `LOAD_FUNC` required them (`steamclient_init` failed). | Optional loading with a `WARN`. Without the export, `IsKnownInterface` returns `true` and the real interface lookup decides; `NotifyMissingInterface` does nothing. |
| `40a8b6c` | `unixlib.cpp` | `std::max(...)` clashes with the `max()` macro from `minwindef.h`. | `(std::max)(...)` |
| `eaa9084` | `unix_private.h` | `winbase.h` poisons `wcsncpy`/`strncpy` with macros; libc++ on macOS includes `wchar.h` afterwards and fails. | Include `string.h` and `wchar.h` before `windef.h`/`winbase.h`. |
| `7963a85` | `unix_steam_input_manual.cpp` | `#error` with no VK→native key conversion for macOS (used by `ISteamHTMLSurface::KeyDown/KeyUp`). | VK → `kVK_*` table (HIToolbox/Events.h), which is what CEF expects on macOS. |

The `__APPLE__` branch of `steamclient_init`, which loads `$STEAM_COMPAT_CLIENT_INSTALL_PATH/steamclient.dylib`,
already existed in Proton and works unchanged.

## Build

`scripts/build-proton-modules.sh` mirrors Proton's `make/rules-makedep.mk`: it reuses the `Makefile` generated by
the Wine build, points `SUBDIRS` at the module sources (lsteamclient, steam_helper) and generates the rules with
`makedep`. The unix side is linked against `ntdll.so` through `LDFLAGS`; Proton does it with `UNIX_LIBS`.

## `proton` script (milestone 6)

Commit `8079308`. Every change is behind `IS_DARWIN = sys.platform == "darwin"`.

| Change | Reason |
|---|---|
| `ld_path_var = DYLD_FALLBACK_LIBRARY_PATH` with `files/lib`, keeping `/usr/local/lib:/usr/lib` | Wine `dlopen`s its unix dependencies by name; dyld ignores `LD_LIBRARY_PATH` and, if `DYLD_FALLBACK_LIBRARY_PATH` is set, it replaces the default value. |
| `set_dir_casefold_bit` does nothing | ext4 ioctl. APFS is case-insensitive by default. |
| msync instead of fsync (`eefa427`) | `futex_waitv` only exists on Linux; `WINEFSYNC=1` selects msync on macOS (milestone 4). `PROTON_NO_MSYNC=1` disables it. |
| `use_nvapi = False` | NVIDIA does not apply. |
| OpenVR/OpenXR optional | Not built for macOS. |
| `PROTON_MAC_GFX` (`5bf2829`, `823f91a`) | Graphics backend selector: `dxvk`, `d3dmetal` (the user's GPTK) or `wined3d`. |
| No `wine-preloader` in `run()` | It does not exist on macOS: the loader reserves memory with Mach-O segments. |
| `ActiveProcess\SteamClientDll[64]` → `C:\windows\system32\lsteamclient.dll` | Steam for Mac does not ship `legacycompat/steamclient*.dll`. Copying `lsteamclient` under that name triggers the 32-bit redirection in Valve's loader (meant for the real DLL), and `steam_api.dll` gets stuck in a loop (diagnosed with `sample`: the thread spins inside `steam_api.dll`). Pointing the registry at `lsteamclient` avoids the redirection. |
| `toolmanifest_macos.vdf` | Same as Linux's, but without `require_tool_appid` (there is no Steam Linux Runtime). |

`scripts/package.sh` assembles the tool in `dist/proton-macos` with the same layout as Proton on Linux
(`proton`, `toolmanifest.vdf`, `compatibilitytool.vdf` with `to_oslist macos`, `version`, `files/`). With
`--install` it links it into the `compatibilitytools.d` of the Steam client and of steamcmd.
